# 실제 좌석 선택과 취소표 대기 흐름 설계

## 배경

현재 앱은 여정 조건 화면에서 좌석 등급과 A/B/C/D 열, 행 범위를 먼저 받는다. 취소표 검색은 임의 좌석을 예약한 뒤 배정된 좌석이 조건과 다르면 반납하는 방식이다. 코레일 예약 대기는 같은 화면의 체크박스로 켜기 때문에, 사용자가 어느 열차에 어떤 방식으로 대기를 신청하는지 알아보기 어렵다.

즐겨찾기는 날짜와 열차 번호를 저장하지 않는 모델을 이미 사용한다. 다만 실제 사용에서 잘 동작하지 않는다는 제보가 있으므로 저장, 목록 반영, 불러오기, 다시 조회, 삭제를 서버와 앱을 연결한 상태에서 각각 재현해야 한다. 원인을 확인하기 전에는 날짜나 저장 형식을 문제로 단정하지 않는다.

사용자가 원하는 결과는 다음과 같다.

- 좌석이 있는 열차는 실제 호차와 좌석 현황을 보고 좌석을 지정해 예약한다.
- 매진 열차는 사용자가 고른 좌석들을 허용 범위로 삼아 `취소표 대기`를 시작한다.
- 허용 범위의 좌석이 생기면 서버가 즉시 결제 전 예약으로 확보한다.
- 여러 명이 떨어져 앉아도 되는 경우에는 한 자리만 확보되어도 즉시 알리고 나머지를 계속 찾는다.
- 연속 좌석을 선택한 경우에는 전원이 붙어 앉을 수 있을 때만 한꺼번에 확보한다.
- 결제할 예약이 생기면 좌석, 결제 기한, 코레일 결제 URL을 보여준다.
- 코레일 공식 예약 대기는 자동 취소표 검색과 분명히 구분한다.

## 용어

- **즉시 예약**: 현재 판매 가능한 좌석을 사용자가 골라 결제 전 예약으로 확보하는 기능이다.
- **취소표 대기**: 틈 서버가 선택한 열차와 좌석 후보를 계속 확인하다가 판매 가능한 좌석이 생기면 즉시 확보하는 기능이다.
- **코레일 예약 대기**: 코레일이 운영하는 공식 대기 신청이다. 한 열차의 일반실에 신청하며 좌석 위치는 지정할 수 없다.
- **좌석 후보**: 취소표 대기에서 사용자가 예약해도 좋다고 선택한 좌석의 집합이다. 탑승 인원보다 많이 고를 수 있다.
- **결제 전 예약**: 좌석은 확보됐지만 결제가 끝나지 않은 상태다. 사용자에게 결제 기한과 결제 URL을 제공한다.

화면 문구에서는 `취소표 찾기`를 사용하지 않고 `취소표 대기`로 통일한다. 공식 기능은 항상 `코레일 예약 대기`로 표기한다.

## 전체 화면 흐름

### 1. 여정 조건

기존 `어떤 좌석이 좋으세요?` 영역을 다음과 같이 바꾼다.

1. `좌석 등급 상관없음`을 가로 전체 선택 버튼으로 둔다.
2. 이 버튼을 해제하면 `일반실`과 `특실` 체크박스를 표시한다. 둘 다 선택할 수 있지만 하나 이상은 선택해야 한다.
3. `좌석 등급 상관없음`은 일반실을 먼저 시도하고, 일반실이 없으면 특실도 허용한다. 이 순서를 버튼 설명과 마지막 확인 화면에 표시해 예상하지 못한 특실 요금을 막는다.
4. 좌석 등급을 지정하면 좌석 입력란 대신 다음 안내를 표시한다.

   > 열차를 조회한 뒤 실제 좌석표에서 자리를 선택할 수 있어요.

5. 인원이 두 명 이상이면 `연속 좌석`과 `떨어져도 괜찮음`을 선택한다.
6. 코레일 예약 대기 체크박스와 기존 A/B/C/D·행 범위 입력란은 이 화면에서 제거한다.

`좌석 등급 상관없음`을 고르면 별도의 좌석 지정 단계 없이 현재와 같은 자동 예약으로 진행한다.

### 2. 열차 조회 결과

각 열차 행에서 일반실과 특실 상태를 별도로 보여준다. 사용자가 선택하지 않은 등급은 숨긴다.

- 현재 좌석이 있으면 `좌석 선택` 버튼을 표시한다.
- 매진이면 `취소표 대기` 버튼을 표시한다.
- 코레일 공식 예약 대기가 가능한 일반실에는 `코레일 예약 대기` 버튼도 별도로 표시한다.
- 지원하지 않는 동작은 비활성 버튼으로 남기지 않고 숨긴다. 필요한 이유는 짧은 보조 문구로 설명한다.

한 열차에서 `좌석 선택`을 누르면 즉시 예약용 좌석표로 이동한다. `취소표 대기`를 누르면 같은 열차의 좌석 후보를 정하는 좌석표로 이동한다. 여러 열차에 취소표 대기를 걸 수 있으며, 이때 열차마다 좌석 후보를 따로 저장한다.

`코레일 예약 대기`는 한 편만 신청할 수 있다. 좌석 지정 화면을 거치지 않고, 일반실만 가능하며, 빈자리 자동 검색을 함께 시작하지 않는다.

### 3. 실제 좌석표

좌석표는 열차 종류별 그림을 앱에 고정하지 않는다. 서버가 해당 열차에서 읽은 호차 목록, 객실 등급, 실제 좌석 목록, 판매 가능 여부, 좌석 방향, 창문 위치와 배치 유형을 그대로 화면 모델로 변환한다.

화면은 다음 요소를 제공한다.

- 일반실·특실 탭. 한 등급만 선택했다면 탭을 생략한다.
- 호차 선택 목록과 호차별 남은 좌석 수.
- 좌석 번호, 통로, 창문 위치, 순방향·역방향 표시.
- `선택 가능`, `선택됨`, `판매 완료`, `예약 대상` 상태를 색상과 모양으로 함께 구분한다.
- 현재 선택 수와 필요한 승객 수.
- `맨 앞자리`, `맨 뒷자리`, 확인, 새로고침 버튼.
- 서버 응답에서 좌석 속성을 확실하게 식별할 수 있을 때만 `가족석` 또는 `유아동반석` 필터를 표시한다.

맨 앞자리와 맨 뒷자리는 고정 행 번호로 판단하지 않는다. 현재 호차가 반환한 유효 좌석 중 가장 앞 행과 가장 뒤 행을 계산한다. 복층이나 특수 차량처럼 한 줄로 비교할 수 없는 배치는 서버의 배치 유형을 우선하며, 확실하지 않으면 빠른 선택 버튼을 숨긴다.

가족석은 이름만 추측해 표시하지 않는다. 실제 응답의 호차·좌석 속성 또는 방향 정보로 검증된 좌석만 표시한다. 여러 열차 형식에서 판별 근거가 확인되지 않으면 이번 배포에서는 가족석 필터를 비활성화하고 좌석표에서 직접 고르게 한다.

### 4. 즉시 예약

즉시 예약에서는 탑승 인원과 같은 수의 현재 판매 가능 좌석만 선택할 수 있다.

- `연속 좌석`이면 같은 호차와 등급에서 붙어 있는 유효 조합만 확인할 수 있다.
- `떨어져도 괜찮음`이면 같은 열차 안에서 서로 떨어진 좌석을 선택할 수 있다. 일반실과 특실을 모두 허용했더라도 예약 전에는 실제 등급과 예상 비용 차이를 다시 보여준다.
- 확인 시점에 좌석 현황을 다시 읽는다.
- 좌석이 여전히 판매 가능하면 특정 좌석 지정 예약을 요청한다.
- 다른 사용자가 먼저 가져갔다면 예약 실패로 끝내지 않고 좌석표를 새로고침하며 어떤 좌석이 사라졌는지 알려준다.
- 예약이 만들어지면 결제 전 예약 화면으로 이동하고 좌석, 결제 기한, 결제 URL을 표시한다.

## 취소표 대기 동작

취소표 대기에서는 판매 완료 좌석도 예약 후보로 선택할 수 있다. 선택 결과는 열차·등급·호차별 실제 좌석 식별자로 저장하며 화면에 표시하는 좌석 번호도 함께 보관한다. 클라이언트가 코레일 요청 필드를 직접 만들지 않으며, 서버가 앞서 발급한 짧은 수명의 열차 키와 좌석 식별자만 받는다.

### 조회 순서

1. 기존 간격에 따라 선택한 열차의 판매 상태를 조회한다.
2. 선택한 등급에 좌석이 생겼을 때만 대상 호차의 좌석 현황을 읽는다.
3. 현재 판매 가능한 좌석과 사용자의 좌석 후보를 교차 확인한다.
4. 조건에 맞는 좌석 조합으로 특정 좌석 지정 예약을 요청한다.
5. 좌석 경쟁에서 지면 오류 알림을 남발하지 않고 다음 조회를 계속한다.
6. 예약 성공 결과를 저장한 다음에만 사용자에게 성공 알림을 보낸다.

### 떨어져도 괜찮음

- 후보 중 한 자리라도 생기면 한 명분을 즉시 확보한다.
- 확보할 때마다 `3명 중 1명 예약 완료 · 결제 필요`처럼 앱 내 알림과 푸시 알림을 보낸다.
- 좌석 번호, 객실 등급, 결제 기한, 결제 URL을 알림과 예약 화면에 표시한다.
- 첫 예약의 결제를 기다리지 않고 남은 인원의 검색을 계속한다.
- 이미 확보한 좌석과 이미 사용한 후보는 다음 예약에서 제외한다.
- 일반실과 특실을 모두 선택했다면 서로 다른 등급의 좌석을 각각 확보할 수 있다. 부분 예약 알림마다 등급을 분명히 표시한다.
- 목표 인원만큼 확보하면 취소표 대기를 완료한다.

### 연속 좌석

- 탑승 인원 전체가 같은 열차, 같은 등급, 같은 호차에서 붙어 앉을 수 있는 조합만 허용한다.
- 후보 좌석 안에 가능한 연속 조합이 하나도 없으면 시작 전에 수정하도록 안내한다.
- 일부 좌석만 먼저 확보하지 않는다.
- 전체 조합이 동시에 판매 가능할 때 한 번의 좌석 지정 예약으로 확보한다.
- 성공하면 모든 좌석과 결제 기한을 한 번에 알린다.

연속 여부는 단순히 좌석 문자열을 정렬해 판단하지 않는다. 통로, 행, 좌석 배치 유형과 실제 인접 관계로 판단한다. 일반실과 특실을 섞은 조합은 연속 좌석으로 보지 않는다.

### 결제 기한과 만료

떨어진 좌석을 따로 확보하면 좌석마다 예약 번호와 결제 기한이 다를 수 있다. 앱은 좌석별 상태를 표시한다.

- 결제 전 예약이 유효하면 `결제 필요`로 표시한다.
- 결제가 확인되면 `결제 완료`로 표시하고 남은 좌석 검색은 계속한다.
- 기한이 지나 좌석이 반환되면 해당 인원을 다시 미확보 상태로 바꾸고 취소표 대기를 계속한다.
- 만료와 재검색 시작을 알림으로 남긴다.
- 사용자는 `남은 좌석 대기 중지`, `결제 전 예약 취소`, `전체 중지 및 예약 취소`를 구분해 실행할 수 있다.

결제 URL은 서버가 제공하는 코레일 공식 주소를 사용한다. 브라우저와 서버의 코레일 로그인 세션은 공유되지 않으므로, URL이 특정 예약을 자동으로 열지 못하는 경우에는 예약 번호와 코레일에서 확인하는 방법을 함께 보여준다.

## 서버와 앱 사이 계약

### 열차 키

열차 조회 결과에는 클라이언트가 조작할 수 없는 `trainKey`를 추가한다. 서버는 사용자 계정, 조회 조건, 코레일 열차 객체를 짧은 만료 시간으로 묶어 저장한다. 좌석표와 예약 요청은 이 키를 사용한다. 키가 만료되면 사용자가 같은 조건으로 열차를 다시 조회하도록 한다.

### 좌석표 API

서버는 다음 역할을 분리해 제공한다.

- 열차의 등급별 호차 목록 조회.
- 선택한 호차의 좌석 현황 조회.
- 즉시 예약용 좌석 선택 검증과 예약.
- 취소표 대기용 열차별 좌석 후보 저장.

응답은 화면에 필요한 안전한 필드만 포함한다. 코레일 원본 응답, 세션, 요청 서명 값, 계정 정보는 앱으로 전달하지 않는다.

### 취소표 대기 모델

기존 검색 조건에 다음 개념을 추가한다.

- 열차별 좌석 후보 목록.
- 허용 객실 등급.
- `consecutive` 또는 `independent` 배치 방식.
- 목표 인원, 확보 인원, 남은 인원.
- 좌석별 결제 전 예약 상태와 결제 기한.

기존 `seat_preference` 문자열은 이전 즐겨찾기와 실행 중 검색을 읽기 위해 유지한다. 새 검색은 구조화된 좌석 후보 모델을 사용한다. 구버전 앱이 새 필드를 보내지 않으면 현재 방식으로 동작한다.

부분 예약을 저장한 뒤 프로세스가 재시작되어도 확보 상태와 남은 검색이 복구되어야 한다. 동일 좌석을 두 번 예약하거나 성공 알림을 두 번 보내지 않도록 예약 번호와 좌석 식별자를 기준으로 멱등 처리한다.

## 즐겨찾기

즐겨찾기는 특정 날짜의 특정 열차가 아니라 다시 사용할 여정 틀로 저장한다.

저장 항목은 다음과 같다.

- 이름.
- 출발역과 도착역.
- 출발 시간 범위.
- 열차 종류.
- 허용 좌석 등급.
- 인원과 좌석 배치 방식.
- 열·행 같은 기존 일반 선호 조건.

출발 날짜, 선택 열차 번호, 실제 좌석 후보, 만료된 열차 키는 저장하지 않는다. 즐겨찾기를 불러오면 다음 이용 가능한 날짜를 기본값으로 넣고 사용자가 날짜를 확인한 뒤 열차를 새로 조회한다. 이 동작은 기존 모델의 의도와 같다.

먼저 모바일 API를 통해 저장·목록·불러오기·다시 조회·삭제를 한 번씩 재현한다. 확인된 결함은 회귀 테스트로 고정한 다음 고친다. 각 변경 결과는 서버에서 다시 읽어 화면과 맞추고, 실패하면 성공 토스트를 띄우지 않는다. 좌석 후보는 열차와 날짜에 종속되므로 새 즐겨찾기에도 넣지 않는다.

## 오류 처리

- 좌석표 조회 실패와 남은 좌석이 없는 상태를 구분한다.
- 좌석표가 오래됐으면 예약 직전에 다시 확인한다.
- 특정 좌석 예약 경쟁에서 진 것은 취소표 대기 전체 실패로 처리하지 않는다.
- 로그인 만료는 계정 재연결이 필요한 상태로 전환하고 검색이 정상 작동 중이라고 표시하지 않는다.
- 지원 여부를 확인하지 못한 차량은 추정 좌석표를 그리지 않는다.
- 가족석 판별이 불확실하면 가족석이라고 표시하지 않는다.
- 부분 예약을 확보한 뒤 나머지 검색이 실패해도 이미 확보된 예약과 결제 기한은 계속 보여준다.
- 푸시 전송 실패가 예약 결과를 되돌리지는 않는다. 앱 내 알림과 예약 상태에는 반드시 남긴다.

## 검증

### 자동 검증

프런트엔드에서는 다음을 확인한다.

- 좌석 등급 상관없음과 일반실·특실 복수 선택 전환.
- 매진·판매 가능·코레일 예약 대기 가능 상태별 열차 행 버튼.
- 호차와 좌석표 렌더링, 인원수 제한, 접근성 이름.
- 즉시 예약 좌석 경쟁 후 새로고침.
- 떨어진 좌석의 `1/3`, `2/3`, `3/3` 부분 예약 표시.
- 연속 좌석에서 일부 좌석을 예약하지 않는 동작.
- 즐겨찾기의 저장·목록 반영·불러오기·다시 조회·삭제와 좌석 후보를 복원하지 않는 동작.

서버에서는 다음을 확인한다.

- 만료되거나 다른 사용자의 열차 키 거부.
- 좌석 원본 식별자와 표시 번호를 혼동하지 않는 예약 요청.
- 좌석 경쟁 실패 후 검색 지속.
- 부분 예약 저장 직후 알림 생성과 재시작 복구.
- 결제 전 예약 만료 후 남은 인원 재검색.
- 연속 좌석 인접 판정과 객실 등급 혼합 거부.
- 같은 예약 결과의 중복 저장·중복 알림 방지.
- 코레일 예약 대기와 취소표 대기의 동시 실행 방지.
- 기존 조건과 즐겨찾기 데이터 호환.

저장소 기본 검증인 `npm test`, `npm run build`, `npm run build:demo`, `uv run --frozen pytest tests/unit -q`, `uv run --frozen ruff check src tests`, `scripts/build-android.ps1`을 모두 통과해야 한다.

### 실서비스 검증

먼저 상태를 바꾸지 않는 조회만으로 다음을 확인한다.

- 현재 운행 열차의 일반실·특실 호차 목록.
- 서로 다른 차량 형식의 실제 좌석 수와 배치 유형.
- 판매 가능 좌석과 판매 완료 좌석 구분.
- 매진 열차에서도 좌석 후보를 고를 수 있을 만큼 좌석표가 반환되는지 여부.
- 맨 앞자리·맨 뒷자리 계산.
- 가족석 또는 유아동반석을 판별할 명시적 근거.

실제 좌석 확보 검증은 서버의 기존 검색·예약 상태가 없는지 확인한 뒤 별도 승인된 한 건으로 진행한다. 좌석 지정 예약 성공, 앱의 결제 전 예약 표시, 푸시 알림, 결제 URL을 확인하고 결제하지 않는다. 테스트로 만든 결제 전 예약은 검증 후 취소하며 취소 결과까지 확인한다.

Android 기기에서는 세로 화면에서 일반실·특실 좌석표, 긴 호차 목록, 부분 예약 카드와 결제 버튼을 확인한다. 결과 화면과 알림, 서버 로그에서 계정·세션·예약 번호 같은 민감정보는 가리고 증거를 남긴다. 데모 좌석표는 실서비스 검증 증거로 사용하지 않는다.

## 구현 순서

1. 즐겨찾기의 저장·목록·불러오기·다시 조회·삭제를 재현하고 확인된 문제를 회귀 테스트와 함께 고친다.
2. 코레일 좌석 조회를 모바일 API의 읽기 전용 계약으로 감싼다.
3. 실제 응답으로 일반실·특실·매진 열차 좌석표의 지원 범위를 확인한다.
4. 앱의 좌석 등급 선택과 열차 행 동작을 바꾼다.
5. 실제 좌석표와 즉시 좌석 지정 예약을 연결한다.
6. 구조화된 좌석 후보와 취소표 대기 검색을 추가한다.
7. 부분 예약 저장·알림·만료 복구를 추가한다.
8. 연속 좌석 판정과 전체 좌석 동시 확보를 추가한다.
9. 전체 자동 검증과 Android 실기기 검증을 수행한다.
10. 실제 예약 검증은 별도 승인 경계에서 수행한다.

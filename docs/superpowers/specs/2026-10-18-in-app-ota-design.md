# 앱 내 웹 번들 업데이트

사용자는 APK를 매번 다시 설치하지 않고 설정의 업데이트 버튼으로 화면과 웹 로직을 바꾸고 싶다. Capacitor Android 7의 로컬 웹 서버를 유지하면서 검증한 웹 번들만 앱 전용 저장소에서 연다. 새 네이티브 기능은 APK 업데이트가 필요하다. 첫 OTA 지원 APK도 한 번 설치해야 한다.

## 선택

- 수동 확인 → 적용 확인 시트 → 다운로드·검증 → WebView 다시 열기. 자동 적용하지 않는다.
- 외부 서비스와 새 의존성 없이 기존 Android/Node 암호화·ZIP API를 사용한다. 원격 웹 사이트를 그대로 여는 방식은 채택하지 않는다.
- 빌드에 HTTPS 매니페스트 주소와 RSA 공개키를 함께 고정한다. 미설정 빌드는 이용 불가를 표시한다. 개인키는 파일로 입력하며 저장소·앱에 넣지 않는다.
- 매니페스트는 `{payload,signature}`이다. payload는 base64 UTF-8 JSON, signature는 decoded payload의 RSA-SHA256 서명이다. JSON 필드는 `schema:1,version,sequence,nativeVersion,url,sha256`. sequence는 양의 안전한 정수이고 nativeVersion은 설치한 APK versionName과 정확히 같다.
- ZIP은 root index.html을 포함한다. HTTPS 다운로드, 서명과 SHA-256, sequence 재생 방지, 경로 탈출·중복 경로·파일 수·용량 제한을 검증한다. 다운로드 20MiB, 해제 50MiB, 항목 2000개를 넘지 않는다.
- 적용 전 이전 경로와 미확정 상태를 동기적으로 저장한다. 새 화면이 30초 안에 ready를 알리지 못하거나 미확정 상태로 다음 실행이 시작되면 이전 번들로 복구한다. APK가 바뀌면 APK 내 번들로 돌아간다. 세션과 사용자 저장소는 유지한다.
- ready는 첫 앱 화면이 그려진 뒤 호출한다. 서버 연결과 로그인 성공은 업데이트의 정상 실행 조건이 아니다.
- 앱 시작 시 받은 bootId를 ready에 돌려주며 네이티브는 세대와 현재 번들 경로를 함께 확인한다. 프로세스 전체의 설치 락과 Activity 종료 취소로 이전 인스턴스가 결과를 뒤늦게 반영하지 못하게 한다.

## UI와 실패

설정에 설치 APK 버전과 현재 화면 버전, 업데이트 상태와 버튼을 표시한다. 확인 중·최신·새 버전·APK 필요·확인 실패·적용 중·적용 실패를 구분한다. 오류를 최신이라고 표시하지 않는다. 적용 시 입력 중인 내용이 사라질 수 있음을 시트에서 알린다. 데모·체험에서는 실제 업데이트를 실행하지 않는다.

## 산출과 검증

전용 production 웹 빌드는 API 주소·데모 여부·기준 APK 버전을 provenance에 남긴다. 로컬 도구는 이 정보를 검증한 뒤 서명된 manifest와 ZIP을 만든다. 생성은 업로드나 운영 배포를 수행하지 않는다. 네이티브 보안·복구 테스트, 실제 산출 도구 실행 테스트, 앱 상태 테스트 및 Playwright 레이아웃 검사를 실행한다. 운영 업데이트 주소·키 설정과 지원 APK 배포는 별도 릴리스 작업이다.
